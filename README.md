# OCR عربي للـ PDF — Browser-only Arabic OCR

Turn scanned PDFs and images into **searchable, selectable Arabic PDFs** entirely inside the browser.
No backend, no API keys, no uploads: files never leave the device.

**Live demo:** https://nhadalqysy985-oss.github.io/ocr-pdf/

## Features

- Arabic RTL, mobile-first UI with light/dark mode.
- PDF, JPG, PNG, WebP and other bitmap images; multiple files at once.
- Per-page rendering with PDF.js at 3× (configurable 2×/3×/4×), longest side capped at 4500 px.
- Page cleanup before OCR:
  - grayscale conversion,
  - 1 %–99 % percentile contrast stretch,
  - optional Otsu binarization (great for faded scans; produces smaller PDFs),
  - automatic deskew (±5°) by projection-profile variance, with true canvas rotation.
- Sequential processing with **one reused Tesseract worker**; every canvas is freed (`width = height = 0`) after use.
- Output PDF:
  - original page size preserved (e.g. A4 = 595×842 pt),
  - page image plus an invisible Unicode text layer (generated by Tesseract),
  - all pages merged with pdf-lib.
- Downloads: searchable PDF, UTF-8 TXT with BOM, copy-to-clipboard.
- Per-page status, overall progress, confidence score, clear Arabic error messages.
- **Self-hosted vendor mode with CDN fallback.** The app tries `./vendor/*` first and only falls back to public CDNs if those files are missing.

## Privacy

There is no server component. The PDF/image bytes are read with the File API, rendered to a local canvas, and processed by Tesseract.js inside a Web Worker. In self-host mode all libraries, WASM cores and language data are served from the same origin, so the app works with the network disabled (verified; see [TEST-REPORT.md](TEST-REPORT.md)).

## Pipeline

1. **Render** each PDF page with PDF.js (`scale = 3`, capped at 4500 px on the longest side). Images use `createImageBitmap`.
2. **Clean** the canvas: grayscale → contrast stretch (1 %/99 %) → optional Otsu. Estimate skew with projection-profile variance over −5°…+5° (0.1° steps, margins cropped) and rotate the canvas.
3. **Recognize** with `worker.recognize(canvas, {}, { pdf: true, text: true })`. `data.pdf` is a single-page PDF with the page image and an invisible text layer; `data.text` is logical-order text.
4. **Merge** all page PDFs with pdf-lib `copyPages`, preserve the source page size, and offer PDF/TXT/copy.

## Run locally

Because the app uses Web Workers and `fetch`, serve it over HTTP (not `file://`):

```bash
cd ocr-pdf
python -m http.server 8000
# open http://localhost:8000/
```

Or use any static server / GitHub Pages.

## Offline / self-host

The vendor folder is complete: PDF.js script + worker, Tesseract.js script + worker, LSTM WASM core (SIMD and non-SIMD fallbacks), `ara.traineddata.gz`, `eng.traineddata.gz`, and all license files. `workerPath`, `corePath` and `langPath` point at these local files when they load successfully. Language data is cached by Tesseract.js in IndexedDB after the first run.

If `vendor/` is absent, the app loads the same versions from cdnjs/jsDelivr and tessdata.projectnaptha.com, and uses CDN worker/core/lang paths.

## Browser support

Current Chrome, Edge, Firefox and Safari (WebAssembly + Canvas 2D + Web Workers). OCR speed and memory depend on page count/resolution; a 2-page A4 scan at 3× takes roughly 25–30 s on a laptop-class CPU.

## Accuracy

On a synthetic scanned-style Arabic exam paper (2 A4 pages, +1.35°/−0.9° rotation, scanner noise):

| Mode | Char accuracy | Word accuracy | Search probes |
|---|---|---|---|
| Default: 3×, contrast, deskew | **98.58 %** | 94.03 % | 10/10 |
| 4× + Otsu, deskew | **100 %** | 100 % | 10/10 |

Accuracy is measured on the text extracted from the downloaded PDF with PDF.js `getTextContent()`, after applying the standard inverse bidi reordering that PDF.js requires for RTL text (see the report). See [TEST-REPORT.md](TEST-REPORT.md) for methodology and full live/offline results.
